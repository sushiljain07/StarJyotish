# How to add a language

Adding a language is one locale file plus one registry entry per side. No
component or service should need a code edit. Never compare a language code
against a literal; use the helpers below.

1. **Locale file.** Add `frontend/src/i18n/xx.json` beside `en.json`, with every key in `en.json`.
2. **Registry entries.** Add one entry to `LANGUAGES` in `frontend/src/i18n/languages.js` (`code`, `label`, `nativeName`, `locale`, `script`, optional `scriptRange`) and one to `SUPPORTED_LANGUAGES` in `backend/services/i18n.py` (`name`, optional `script`). The locale file is picked up automatically by `import.meta.glob` in `frontend/src/i18n/index.js`.
3. **Fonts.** Add the script's font to `frontend/index.html` and to the Tailwind font stacks. `<html data-script>` is set from the registry entry's `script`, so CSS can key off it.
4. **Backend templates.** Translate the backend tables (`YOGA_TEXT` and the other `text()` tables, including the per-language `_MAHAPURUSHA` and `_MAHAPURUSHA_TEXT` tables in `services/yoga_text.py`, which fall back to English silently, plus the `*_LANG_RULE` prompt tables in `services/ai.py`, `services/career_analysis.py`, `services/relationship_analysis.py` and `services/i18n.py`). Lookups fall back to English, so a missing entry degrades rather than breaks.
5. **Glossary.** Add a section for the language to [`docs/i18n-glossary.md`](i18n-glossary.md): the word chosen for each recurring term, and which rows the parity tests enforce.
6. **Parity tests.** Run `npx vitest run` in `frontend/` and `.venv/bin/pytest -q` in `backend/`.

Helpers: frontend `currentLanguage()`, `localeFor(code)`, `scriptFor(code)`, `languageEntry(code)`; backend `normalize_language`, `language_name`, `language_instruction`, `text`, `ordinal`. Unknown language codes fall back to English on both sides (the API does not return 422).
