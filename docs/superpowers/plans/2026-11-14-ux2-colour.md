# UX Slice 2: Colour Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (faster mode, approved by the owner). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Finish the colour system so the app reads as one production-quality palette:
- every text colour passes AA on its real surface, light or night;
- colours come only from tokens;
- planets get one readable palette;
- selected tabs are always gold.

**Architecture:**
- Task 1 moves every colour value into one source, `src/theme/tokens.js`. `tailwind.config.js`, `chartPalette.js` and `planetColors.js` all import it, which also stops the Tailwind config being bundled into the app.
- Task 1 also adds the missing night-surface and planet tokens, with contrast tests.
- Tasks 2–5 migrate disjoint sets of files onto those tokens and run in parallel worktrees.
- Task 6 adds the guard tests that keep it that way.
- Task 0 first deletes components that are never mounted, so nobody recolours dead code.

**Tech Stack:** React 18, Vite, Tailwind 3.4, Vitest, Playwright (browser pass).

**Spec:**
- `docs/superpowers/audits/2026-11-14-ux-audit.md`: §3 "Colour scheme", plus issues C1–C8, X5 and the planet palette.
- The 5a follow-ups in the roadmap.
- The owner decisions recorded in Global Constraints.

## Global Constraints

- **Branch** `feat/ux2-colour`, from `main` (which includes 5a and UX1). The PR targets `main`.
- **Owner decisions (14 Nov):**
  - (a) Selected tabs and pills are **always gold** everywhere. Sage and mauve remain only as soft content tints.
  - (b) A new AA planet palette, used everywhere:

    | Planet | Colour |
    |---|---|
    | Sun | #B83232 |
    | Moon | #6B4BA8 |
    | Mars | #8B2A2A |
    | Mercury | good #3F6B45 |
    | Jupiter | primary.ink #86621E |
    | Venus | mauve #8C5B73 (or its darkened value from Task 1) |
    | Saturn | #2F5AA8 |
    | Rahu | #4A4458 |
    | Ketu | #7A4A2A |
    | Uranus, Neptune, Pluto | pick AA-safe values in the same family, and say which |

    Night variants are needed for /home.
  - (c) Faster mode: parallel worktrees for Tasks 2–5, one review per task, one browser pass at the end.
- **AA rules:**
  - Text on its actual background must reach 4.5:1, or 3:1 for text ≥18.66px bold / ≥24px.
  - Decorative glyphs are exempt but must be `aria-hidden`.
  - Ratios come from `src/theme/contrastUtil.js` (`ratio`, `composite`).
- **Minimum readable text size on /home is 11px.** Anything smaller must be decorative.
- **Copy:** no English or Hindi copy changes. No `'hi'` literals. Tap targets stay ≥44px. The ratchets in `src/theme/tokenUsage.test.js` must not go up.
- **Commands:**
  - Frontend: `npm test` (it must stay deterministic), `npm run lint` (0 errors), `npm run build`. Restore `public/sitemap.xml` after a build.
  - Backend: untouched.
  - After code changes, run `graphify update .`.
- **Parallel worktrees (Tasks 2–5):**
  - Each task edits only the files it lists.
  - Each task may regenerate `src/theme/baselines/token-usage-baseline.json` in its own worktree. The controller resolves baseline conflicts at merge by regenerating it.
  - No task edits `tailwind.config.js` or `src/theme/tokens.js` after Task 1. If one needs a token, it stops and asks.

## Review Focus

1. **Night surfaces must not get parchment-tuned colours.** After the migration, any sage, mauve, vermillion, good, bad or ink-muted text on a night background is a regression. Task 6's reverse guard pins this.
2. **Planet colours on the dark /home cards** must use the night variants. Light-palette planet colours fail on night.
3. **Selected tab text on gold.** It must be `text-night`, which is AA on #D9A441. White on gold fails.
4. **Deleting components must not break routes or tests.** Task 0 must prove each one is unimported, with grep and the build.
5. **Ashtakavarga legend and cells must keep matching**, and stay distinguishable, after the "strong" band changes.
